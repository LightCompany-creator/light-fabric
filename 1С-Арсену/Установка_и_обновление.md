# Установка и обновление приложения на сервере фабрики

Для Арсена. Цель: поставить один раз, дальше обновления приходят сами,
без пересборки и без участия 1С-программиста.

## Откуда брать сборку

Готовые сборки лежат в GitHub, раздел Releases:
https://github.com/LightCompany-creator/light-fabric/releases

В каждом выпуске архив `lightfabric-<версия>.zip` (папка `lightfabric` со
статикой и `web.config` для IIS) и два скрипта обновления. Собирать из
исходников больше не нужно.

## Сервер serv2 (по письму Арсена от 26.10.2026)

Приложение: `http://serv2/lightfabric/`, сервис 1С: `/workf/hs/lf/v1`.
Выпуски начиная с 2026.10.26-1 собраны на этот сервис; выпуски 2026.10.23-*
были с заглушкой, их на serv2 ставить не нужно.

Windows Server 2008 R2 с PowerShell 2.0: скрипт `update-lightfabric.ps1`
переписан под него (без Invoke-WebRequest, ConvertFrom-Json, Expand-Archive).
Единственное жёсткое требование: **TLS 1.2**, GitHub другого не принимает.
Для этого нужны:

1. .NET Framework 4.5 или новее на сервере.
2. PowerShell, запущенный на .NET 4, одно из двух:
   - поставить WMF 5.1 (нужен Server 2008 R2 SP1 и .NET 4.5.2), это
     нормальный путь, скрипт и дальше будет работать без оговорок;
   - или оставить PowerShell 2.0, но положить рядом с `powershell.exe`
     (в `C:\Windows\System32\WindowsPowerShell1.0\`) файл
     `powershell.exe.config`:

     ```xml
     <?xml version="1.0" encoding="utf-8"?>
     <configuration>
       <startup useLegacyV2RuntimeActivationPolicy="true">
         <supportedRuntime version="v4.0.30319" />
         <supportedRuntime version="v2.0.50727" />
       </startup>
     </configuration>
     ```

     Тогда PowerShell 2.0 работает на .NET 4, и TLS 1.2 включается числом
     3072, как скрипт и делает.
3. TLS 1.2 включён в системе (на 2008 R2 по умолчанию может быть выключен):
   обновление KB3140245 и в реестре
   `HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.2\Client`
   значения `Enabled=1`, `DisabledByDefault=0`.

Скрипт при запуске сам проверяет версию .NET и пишет в журнал, чего не
хватает. Если ничего из этого ставить нельзя, остаётся ручной путь: скачать
архив выпуска на любом компьютере и положить папку `lightfabric` на сервер.

## Первая установка (один раз)

1. Скачать архив последнего выпуска, распаковать папку `lightfabric` в корень
   сайта рядом с публикацией 1С, чтобы открывалось
   `http(s)://<сервер>/lightfabric/`. Имя каталога менять нельзя, оно зашито
   в сборку.
2. Скрипт `update-lightfabric.ps1` положить, например, в `C:\lightfabric\`.
   Если корень сайта не `C:\inetpub\wwwroot`, указать свой параметром
   `-SiteRoot`.
3. Проверить вручную:

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File C:\lightfabric\update-lightfabric.ps1
   ```

   Скрипт скажет «Стоит актуальная версия …». Нужен выход с сервера
   в интернет на `github.com` и `api.github.com`, входящих соединений нет.
4. Поставить в планировщик, от имени SYSTEM, каждые 30 минут:

   ```
   schtasks /Create /TN "LightFabric update" /SC MINUTE /MO 30 /RU SYSTEM /F /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\lightfabric\update-lightfabric.ps1"
   ```

   Обновление посреди смены безопасно: данные живут в 1С, черновик смены
   на планшете сохраняется, новая версия подхватывается при следующем
   открытии приложения.

   Для Linux то же делает `update-lightfabric.sh` (переменные `SITE_ROOT`,
   `FOLDER`), строка для cron внутри скрипта.

## Как это работает дальше

- Новая версия появляется в Releases только по нашему решению: что-то
  исправили, проверили, выпустили. Промежуточные правки на сервер не идут.
- Скрипт при запуске сравнивает версию в Releases с `version.json` в папке
  приложения. Новее: скачивает, распаковывает рядом, меняет папки местами.
  Старая версия остаётся в `lightfabric.prev`.
- Если выпуск требует изменений в 1С, в его описании стоит «Нужна 1С: да»
  и что именно. Такой выпуск мы не публикуем, пока вы не подтвердите свою
  часть, поэтому автообновление его не подхватит раньше времени.
- Какая версия стоит: внизу экрана входа написано «Сборка …», то же
  в `version.json`. Журнал обновлений: `update-lightfabric.log` в корне сайта.

## Откат

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\lightfabric\update-lightfabric.ps1 -Rollback
```

Возвращает предыдущую папку. Следующий плановый запуск снова поставит
последний выпуск, поэтому после отката напишите нам, мы выпустим исправление.

## Что нужно от вас, чтобы сборка пошла в настоящую 1С

Относительный путь HTTP-сервиса на этом же сервере, вида `/база/hs/lf/v1`.
Мы впишем его в параметры сборки, и следующий выпуск будет ходить в 1С
вместо заглушки. Запросы идут на тот же адрес, что и страница, CORS не нужен.
