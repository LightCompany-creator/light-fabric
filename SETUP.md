# SETUP: запуск и развёртывание LightFabric

> Для Арсена (1С-программист Light Company), сисадмина фабрики и любого
> разработчика, кому нужно поднять приложение или посмотреть, как оно работает.
> Обновлено 24 сентября 2026 под архитектуру из контракта обмена
> (`1С-Арсену/Контракт_1С_LightFabric_этап1.md`).

---

## 1. Как устроено приложение

**1С это единственная база данных и единственный сервер.** У приложения нет
своей базы: оно хранит на планшете только кэш сеанса. Справочники, остатки
и документы живут в 1С, туда же уходят смены и перемещения.

Отсюда простое следствие для развёртывания: приложение это набор файлов,
которые отдаются браузеру планшета. Вся работа идёт в браузере, а данные
он берёт из 1С напрямую.

- **Стек:** Next.js 14 (App Router), TypeScript, Tailwind, shadcn/ui
- **Node.js:** 20 LTS (нужен для сборки; на боевом сервере, см. §5, может
  не понадобиться вовсе)
- **Обмен с 1С:** HTTP-сервис 1С, JSON, Basic Auth учётной записью 1С

### Переходный период

В репозитории сейчас два раздела:

| Раздел | Маршруты | Состояние |
|---|---|---|
| Цеховое приложение на 1С | `/enter`, `/w/**` | Актуальное, развиваем |
| Старое приложение на Supabase | `/login`, `/dashboard`, `/shifts`, `/orders` и т.д. | Работает, но уйдёт после перехода на боевую 1С |

Старое трогать не нужно: на фабрику пойдёт только раздел `/w`. Заказы
из старого раздела вернутся на втором этапе, уже поверх 1С.

## 2. Быстрый запуск: посмотреть, как всё работает

Сервис 1С ещё не опубликован, поэтому приложение умеет работать на заглушке.
Она отвечает ровно так, как описано в контракте v0.2, включая неприятные случаи:
смену, которая закрылась, но ждёт отражения в учёте, закрытый месяц, расхождение
версий, ошибки ввода списком.

```bash
git clone https://github.com/LightCompany-creator/light-fabric.git
cd light-fabric
npm install
npm run dev
```

Открыть `http://localhost:3000/enter`.

- логин любой, например `цех_литейка`, пароль любой;
- чтобы получить права администратора, войдите под логином `админ`
  (в боевой версии права определяет сама 1С);
- в заглушке доступны все семь цехов: Литьё, Крой, Швейка, Обшив, Клеевая,
  Маркировка, Склад ГП.

Что попробовать: открыть смену, внести выработку и простой, подтвердить итог
выпуска, закрыть смену, затем передать продукцию в соседний цех и подтвердить
приём со стороны получателя (переключив цех сверху).

Демо-данные повторяют цепочку фабрики: Литьё делает галоши из пластиката,
Крой кроит заготовки, Швейка шьёт из них носки, Обшив собирает сапог
из галоши и носка. Если передать в цех меньше, чем он хочет израсходовать,
приложение покажет нехватку и не даст закрыть смену.

### Режим «нет связи»

Чтобы увидеть работу без сети, в консоли браузера:

```js
localStorage.setItem("lf.1c.mock.offline", "1")   // связь пропала
localStorage.removeItem("lf.1c.mock.offline")     // связь вернулась
```

Приложение продолжит работать на данных, сохранённых на планшете, а введённое
уйдёт в 1С, когда связь восстановится.

Медленную сеть изображает другой ключ, задержка ответа в миллисекундах:

```js
localStorage.setItem("lf.1c.mock.latency", "2000")
```

Полезно, чтобы увидеть индикатор «сохраняю» и убедиться, что правки во время
отправки не теряются.

## 3. Подключение к настоящей 1С

Нужна одна переменная окружения:

```
NEXT_PUBLIC_API_1C_URL=/<база>/hs/lf/v1
```

Адрес относительный, потому что приложение лежит на том же веб-сервере,
что и 1С. Полный адрес (`https://<сервер>/<база>/hs/lf/v1`) тоже годится,
но тогда на стороне 1С понадобятся кросс-доменные заголовки.

Как только она задана, заглушка отключается и приложение работает с 1С.
Пользователи заводятся в 1С, приложение своих не держит: логин и пароль
из формы входа уходят в заголовке `Authorization` каждого запроса.

> Ключи Supabase для раздела `/w` не нужны: он их не спрашивает. Они нужны
> только старым экранам, см. §7.

### Что должно быть готово со стороны 1С

1. **HTTP-сервис опубликован** по адресу из переменной выше.
2. **HTTPS с нормальным сертификатом желателен, но не обязателен.** Само
   приложение по `http://` работает полностью. Без HTTPS Chrome на Android
   не предложит установить его иконкой и не включит работу без сети; Safari
   на iPad иконку поставит, но тоже без офлайна. Самоподписанный сертификат
   не поможет: планшеты ему не доверяют.
3. **Пользователи 1С** для начальников цехов, склада готовой продукции
   и администратора, с правами на свои склады.
4. **Кросс-доменные запросы разрешены**, если файлы приложения лежат не на том
   же сервере, что и 1С: предварительный запрос `OPTIONS` и заголовки
   `Authorization`, `If-Match`, `Idempotency-Key`, `Content-Type`.
   Если приложение лежит рядом с 1С (см. §5), этого не требуется вовсе.

## 4. Проверка после подключения

По шагам, каждый следующий имеет смысл только после предыдущего:

1. Открыть `/enter`, войти учётной записью 1С. Если видно имя пользователя
   и его цеха, значит `/me` работает и права настроены.
2. На рабочем месте должны появиться сотрудники, виды работ, продукция,
   материалы и остатки склада. Это один запрос контекста цеха.
3. Открыть смену: в 1С должен появиться документ «Отчёт начальника цеха»
   в статусе черновика.
4. Внести выработку, подтвердить итог выпуска, закрыть смену. Смена должна
   закрыться, а на экране появиться «Отражена в учёте» с номером отчёта
   производства. Если вместо этого «Ждёт отражения в учёте», под надписью будет
   причина словами 1С: это вопрос учёта, а не обмена.
5. Передать позицию в другой цех и подтвердить приём с обеих сторон. Остаток
   должен уйти у отправителя и появиться у получателя только после второго
   подтверждения.

Если что-то отказывает, приложение показывает причину словами 1С. Это нормальный
рабочий режим, а не сбой: 1С здесь единственный судья.

## 5. Развёртывание на фабрике

Цель: файлы приложения лежат на сервере фабрики, планшеты открывают их
по внутреннему адресу, данные не покидают периметр.

**Рекомендуемый вариант: рядом с публикацией 1С.** Тогда браузер планшета
обращается к 1С на тот же адрес, кросс-доменных запросов нет, настраивать
ничего дополнительно не нужно.

**Статическая сборка (основной вариант для фабрики).** Цеховой раздел
собирается в папку с обычными html, js и css, которую кладут рядом
с публикацией 1С. Node.js на сервере не нужен.

```bash
npm install
npm run build:static                                   # заглушка 1С, каталог /lightfabric
npm run build:static -- --api /база/hs/lightfabric     # боевой адрес сервиса
npm run build:static -- --base /lf                     # другое имя каталога
```

Результат: `dist/lightfabric/` (с `web.config` для IIS), рядом архив
`dist/lightfabric-static-<дата>.zip` и памятка `dist/УСТАНОВКА.md` для того,
кто ставит на сервер. Имя каталога и адрес сервиса зашиваются в сборку,
поэтому под другой каталог нужна пересборка.

Как это работает: `scripts/build-static.mjs` на время сборки убирает из проекта
старый раздел на Supabase (серверные действия и middleware со статикой
несовместимы), собирает `next build` в режиме экспорта и возвращает всё
на место, даже если сборка упала. В репозитории ничего не меняется.

**Запасной вариант с сервером Next** (если по какой-то причине нужна
серверная часть):

```bash
npm run build
npm run start      # слушает порт 3000
```

Дальше веб-сервер фабрики (Apache, IIS, nginx) проксирует нужный адрес
на `localhost:3000`, либо приложение запускается как служба.

**Чего делать не нужно:** ставить базу данных, настраивать Supabase, держать
включённым чей-то рабочий компьютер. Приложение без 1С бесполезно, а с 1С ему
не нужно ничего, кроме раздачи файлов.

## 6. Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер на :3000. Service worker в этом режиме отключён |
| `npm run build` | Прод-сборка с проверкой TypeScript и ESLint |
| `npm run build:static` | Статическая сборка цехового раздела под каталог сервера 1С, см. §5 |
| `npm run start` | Запуск прод-сборки |
| `npm run lint` | Только ESLint |
| `npm run check:api1c` | Проверка клиента 1С на подставном сервере: ответы без JSON, относительный адрес, ключи, закрытие |

Не запускать `npm run build`, пока работает `npm run dev`: ломается кэш `.next`.

PWA (установка на планшет иконкой, работа без сети) работает только
на прод-сборке и только по HTTPS или на `localhost`.

## 7. Что осталось от старой архитектуры

Это важно понимать, чтобы не настраивать лишнего:

- `.env.local` с ключами Supabase нужен **только** старым экранам. Раздел `/w`
  работает без него: проверено на прод-сборке с убранными ключами. Старые
  маршруты вроде `/login` в этом случае отдают ошибку сервера, и это ожидаемо:
  на фабрику они не поедут.
- `schema.sql`, `supabase/migrations/**`, скрипты `seed-*.mjs` относятся
  к старой базе. Для работы с 1С они не нужны и на фабрику не переносятся.
- Демо-аккаунты `@lightflow.test` относятся к старому входу. В новом разделе
  пользователи только из 1С.
- Next.js 14.2.35 это последняя версия ветки 14.2, обновляться внутри неё некуда.
  В самом Next есть критические уязвимости, закрытые только в 16.x, но все они
  касаются серверной части. На фабрике приложение планируется как статика,
  без серверного Next, поэтому к боевому контуру они не относятся.
  Проверено репетицией статической сборки: собирается, если убрать старый раздел.
  Экраны смены и передачи уже переведены на адреса с параметром
  (`/w/shift?id=…`, `/w/transfer?id=…`), других препятствий у статики нет.

Спецификация обмена и переписка с 1С лежат в папке `1С-Арсену/`.
