# Дополнение к контракту, v0.3: несколько цехов у пользователя и несколько складов у цеха

Черновик от 22.10.2026, по фактам с фабрики. Для обсуждения с Арсеном.

## 1. Факты

1. Один начальник производства ведёт несколько цехов: Литейка ЭВА, Литейка
   ПВХ, Упаковка ЭВА, Упаковка ПВХ. Входит с одной учётной записью, выбирает
   цех, открывает смену. У каждого цеха свои работники и своя номенклатура
   (продукция, виды работ), в 1С это разные подразделения.
2. У цеха несколько складов: один или несколько складов материалов, откуда
   списывается сырьё, и один склад полуфабриката (промежуточной готовой
   продукции), куда приходуется выпуск этого цеха. Пункт В-2 контракта
   («ровно один склад на цех») этому не соответствует.

## 2. Что уже есть

- `GET /me` отдаёт список `workshops`. Приложение показывает переключатель
  цехов, если их больше одного, и помнит выбор до выхода. Для пункта 1
  достаточно, чтобы 1С отдавала пользователю все его цеха. Код не меняется.
- Контекст цеха (`/workshops/{id}/context`) и так свой на каждый цех:
  работники, виды работ, продукция, материалы, остатки, открытые смены.

## 3. Что предлагаем изменить в контракте

3.1. `WorkshopRef`: вместо одного `warehouse` список
`warehouses: [{ id, code, name, role }]`, где `role` одно из `"materials"`,
`"output"`. Ровно один склад с ролью `output`, складов `materials` один или
несколько. Для совместимости `warehouse` можно оставить равным складу
`output`.

3.2. `context.stock[]` и `GET /workshops/{id}/stock`: у каждой строки
`warehouse_id` и `warehouse_name`. Доступный остаток (остаток минус
неподтверждённые исходящие) считается по складу.

3.3. Закрытие смены (ОПЗС): приход продукции на склад `output`, списание
материалов со складов `materials`. Если один материал лежит на нескольких
складах цеха, два варианта:
- (а) 1С сама выбирает склад по остатку; приложение не меняется;
- (б) приложение передаёт `warehouse_id` в строке `materials[]`.
Мы за (а). Вариант (б) сделаем, если в учёте важно, с какого склада.

3.4. Перемещения: отправка по умолчанию со склада `output` (полуфабрикат),
приём на склад `materials` цеха-получателя. Если у получателя несколько
складов материалов, правило выбора за 1С (по номенклатуре) либо получатель
указывает склад при подтверждении. В `POST /transfers` добавить
необязательные `from_warehouse_id` и `to_warehouse_id`, в документе
передачи отдавать оба склада.

3.5. `transfer_targets` без изменений: это по-прежнему цеха.

3.7. Цех и участки. Литейка ЭВА, Литейка ПВХ, Упаковка ЭВА и Упаковка ПВХ
это участки одного Литейного цеха с одним начальником. В `WorkshopRef`
добавить необязательное `parent: { id, name }` (подразделение-родитель).
Приложение показывает участки сгруппированно: сначала цех, внутри него
выбор участка. Смены, остатки и перемещения ведутся по участку, как по
цеху сейчас.

3.6. Права. Сейчас доступ к цеху даёт ответственность за склад цеха. Со
списком складов: доступ к цеху, если пользователь ответственный хотя бы за
склад `output`, либо отдельная привязка «пользователь → цех» в 1С.

## 4. Что изменится в приложении после согласования

- Рабочее место: остатки сгруппированы по складам, склад полуфабриката
  первым.
- Смена, материалы к списанию: «из N на складе …» с названием склада; при
  варианте (б) выбор склада в строке, когда материал есть на нескольких.
- Новая передача: позиции со склада полуфабриката, ниже материалы.
- Заглушка: один пользователь с четырьмя цехами (Литейка ЭВА, Литейка ПВХ,
  Упаковка ЭВА, Упаковка ПВХ) и склады по ролям, чтобы показать и проверить.
- Выбор цеха сразу после входа крупными кнопками, если цехов несколько
  (задача на холст Claude Design).

2. Списание при материале на нескольких складах: вариант (а) или (б)?
3. Правило склада-получателя при перемещении (п. 3.4).
4. Права по п. 3.6.
5. Подразделения Литейка ЭВА / ПВХ и Упаковка ЭВА / ПВХ: это четыре
   подразделения в 1С (дочерние у «Литейного цеха») или два с признаком?
   От этого зависит список `workshops` и поле `parent` (п. 3.7).
