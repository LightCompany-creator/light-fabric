# Протокол связки Claude Design ↔ Claude Code

Две программы работают в одной папке проекта и общаются через два файла.
Claude Design придумывает, Claude Code делает, Claude Design проверяет.

```
design/ЗАДАЧИ.md   Claude Design пишет, Claude Code читает и меняет статусы
design/ОТЧЁТ.md    Claude Code пишет, Claude Design читает и сверяет
design/screens/    снимки экранов: HTML-слепки и PNG, обновляет Claude Code
```

## Цикл

1. Claude Design смотрит `screens/` и `БРИФ.md`, формулирует задачу
   в `ЗАДАЧИ.md` со статусом `новая`.
2. Claude Code берёт задачи со статусом `новая` по порядку номеров, делает,
   проверяет в браузере, обновляет снимки затронутых экранов, ставит
   `готово` и пишет запись в `ОТЧЁТ.md`.
3. Claude Design открывает новые снимки, сверяет с задумкой. Совпало: ставит
   `принято`. Нет: пишет новую задачу с уточнением, ссылаясь на номер старой.

Как запустить шаг 2: сказать Claude Code «возьми задачи из design».
Чтобы он проверял папку сам, включить `/loop 10m возьми задачи из design`.

## Формат задачи

```
### Д-7. Экран смены: блок «Кто вышел»
Статус: новая
Экран: /w/shift
Что изменить: фамилии в один столбец, кнопка на всю ширину, отмеченные
сверху. Сейчас чипы в три ряда, на планшете в перчатках промахиваются.
Зачем: отметить состав смены за пять секунд, не целясь.
Готово, когда: любая фамилия нажимается с первого раза, отмеченные
видны без прокрутки, остальное не изменилось.
```

Статусы: `новая` → `в работе` → `готово` → `принято`, либо `отклонено`
с причиной от Claude Code.

## Формат отчёта

```
### Д-7. Готово, коммит a1b2c3d
Сделано: ...
Файлы: app/(1c)/w/shift/shift-screen.tsx
Снимки: screens/shift.html, screens/shift.png
Проверил: нажатие по каждой фамилии на 768×1024 и 375×812.
Не сделал: ... (если что-то из задачи не вошло, и почему)
```

## Правила для Claude Code

- Поведение, заданное контрактом с 1С, не меняется: что уходит в 1С,
  когда, какие статусы, какие отказы. Задача, которая это ломает, получает
  статус `отклонено` и объяснение в отчёте.
- Тексты на экране: факт и цифра, без инструкций и объяснений очевидного.
  Деньги и расценки не показываются никогда.
- Каждая задача отдельный коммит с номером задачи в сообщении.
- После правок: типы, линтер, прод-сборка, проверка в браузере,
  обновление снимков.

## Правила для Claude Design

- Одна задача, одно изменение на одном экране. Пять мелких лучше одной
  большой.
- В задаче всегда есть «зачем» для человека в цеху и «готово, когда».
- Не трогать смысл кнопок и полей: их набор идёт из контракта с 1С.
  Менять можно расположение, размер, порядок, цвет, подписи.
- Проверять по снимкам в `screens/`, а не по памяти: Claude Code обновляет
  их после каждой задачи.
